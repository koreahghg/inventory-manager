# inventory-manager

개인적으로 사용하는 **상품 재고·매입·판매·수익 통합 관리 시스템**이다.

신발 및 의류 등의 상품을 매입하여 판매하는 과정에서 발생하는 재고, 매입금액, 판매금액, 수수료, 배송비, 순이익 등의 데이터를 체계적으로 관리하는 것을 목적으로 한다.

## 1. 프로젝트 목적

기존에 엑셀이나 메모 등으로 관리하던 상품 정보를 하나의 웹 시스템에서 관리한다.

상품별 재고 현황을 확인할 수 있으며, 매입과 판매 데이터를 기반으로 누적 금액과 순이익을 자동으로 계산한다.

또한 연도별·월별 통계를 제공하여 특정 기간의 매입, 판매 및 수익 현황을 쉽게 확인할 수 있도록 한다.

## 2. 로그인

개인 사용 목적이므로 회원가입이나 소셜 로그인은 제공하지 않는다.

* 아이디 + 비밀번호 로그인
* 인증되지 않은 사용자는 관리자 페이지 접근 불가
* 비밀번호는 평문으로 저장하지 않고 안전하게 처리
* 로그인 상태 유지
* 로그아웃

## 3. 대시보드

로그인 후 전체 재고 및 거래 현황을 한눈에 확인할 수 있다.

### 주요 지표

* 누적 매입금액
* 누적 판매금액
* 누적 순이익
* 현재 재고 수량
* 현재 재고 매입금액
* 총 판매 상품 수
* 판매율

### 기간별 조회

* 전체
* 연도별
* 월별
* 일별

기간을 선택하면 해당 기간의 매입금액, 판매금액, 순이익 등을 자동으로 계산한다.

## 4. 재고 관리

상품을 등록하고 현재 재고 상태를 관리한다.

### 상품 정보

* 상품 이미지
* 상품명
* 브랜드
* 품번
* 사이즈
* 색상
* 매입가
* 수량
* 매입일
* 매입처
* 물류 코드
* 메모

### 이미지

상품 등록 시 상품 이미지를 업로드할 수 있다.

* 여러 이미지 업로드 지원
* 대표 이미지 지정
* 상품 목록에서 대표 이미지 표시
* 상품 상세 페이지에서 전체 이미지 확인

이미지는 별도의 파일 저장소를 사용하고 DB에는 이미지 URL 등의 필요한 정보만 저장한다.

## 5. 매입 관리

상품을 매입한 기록을 관리한다.

매입 데이터를 기반으로 다음 정보를 확인할 수 있다.

* 매입일
* 상품
* 수량
* 개당 매입가
* 총 매입금액
* 매입처
* 메모

매입 기록은 삭제하거나 임의로 변경하여 통계가 깨지지 않도록 거래 이력을 기준으로 관리한다.

## 6. 판매 관리

재고 상품을 판매 처리할 수 있다.

판매 처리 시 다음 정보를 입력한다.

* 판매일
* 판매가격
* 판매 플랫폼
* 수수료
* 배송비
* 기타 비용
* 메모

판매가 완료되면 해당 상품의 재고 수량이 자동으로 감소하고 판매 내역이 기록된다.

### 순이익 계산

```text
순이익 = 판매금액 - 매입금액 - 수수료 - 배송비 - 기타 비용
```

상품별 순이익과 전체 누적 순이익을 모두 확인할 수 있어야 한다.

## 7. 통계

매입 및 판매 데이터를 기반으로 기간별 통계를 제공한다.

### 연도별

```text
2026년
총 매입금액
총 판매금액
총 순이익
매입 수량
판매 수량
```

### 월별

```text
2026년 9월
총 매입금액
총 판매금액
총 순이익
매입 수량
판매 수량
```

필요한 경우 일별 데이터까지 확인할 수 있도록 한다.

매입·판매 추이를 그래프로 시각화하여 확인할 수 있도록 한다.

## 8. 물류 코드

물류 처리에 사용하는 코드를 관리한다.

물류 코드는 **일회성 사용**을 전제로 한다.

### 등록

관리자가 물류 코드를 등록할 수 있다.

```text
물류 코드
[ ABC123456 ]

[ 등록 ]
```

이미 등록된 코드와 중복되는 경우 등록을 거부한다.

### 사용

등록된 물류 코드를 상품에 연결하거나 물류 처리에 사용하면 해당 코드를 `사용 완료` 상태로 변경한다.

사용 완료된 코드는 다시 사용할 수 없다.

상태는 다음과 같이 관리한다.

```text
사용 가능
사용 완료
```

사용 완료된 코드의 사용일 및 연결된 상품 정보를 확인할 수 있도록 한다.

## 9. 데이터 관리 원칙

재고 수량과 금액을 단순히 현재 값만 저장하는 방식으로 만들지 않고 **매입 및 판매 거래 기록을 기반으로 추적 가능한 구조**로 설계한다.

예를 들어:

```text
매입 +1
↓
재고 1개 증가

판매 -1
↓
재고 1개 감소
```

이를 통해 과거 거래 내역을 확인할 수 있고 연도별·월별 통계를 정확하게 계산할 수 있도록 한다.

## 10. 기술 스택

* Next.js (App Router)
* TypeScript
* Tailwind CSS
* Supabase

  * PostgreSQL
  * Auth
  * Storage

프론트엔드와 서버 기능은 하나의 Next.js 프로젝트에서 관리한다.

## 11. 프로젝트 방향

개인 사용 시스템이므로 불필요하게 복잡한 기능이나 권한 시스템을 추가하지 않는다.

핵심은 다음 네 가지이다.

```text
매입
 ↓
재고
 ↓
판매
 ↓
수익 분석
```

UI는 복잡하지 않고 직관적인 관리자 대시보드 형태로 구성한다.

모바일과 데스크톱 모두 사용할 수 있도록 반응형으로 구현한다.

추후 기능을 추가할 수 있도록 컴포넌트와 데이터 구조는 확장성을 고려하여 설계한다.

## 개발 환경 설정

```bash
cp .env.local.example .env.local
# .env.local에 Supabase 프로젝트 URL / anon key / service role key 입력

npm install
npm run dev
```

## 데이터베이스

`supabase/migrations` 디렉터리에 스키마 마이그레이션 SQL이 있다. Supabase 프로젝트의 SQL Editor에서 순서대로 실행하거나 `supabase db push`로 적용한다.

### 타입 자동 생성

프로젝트를 Supabase CLI에 연결한 뒤에는 DB 스키마로부터 TypeScript 타입을 자동 생성할 수 있다.

```bash
npx supabase login
npx supabase link --project-ref <project-ref>
npm run gen:types
```

## 프론트엔드 아키텍처 (FSD)

`src`는 Feature-Sliced Design 레이어로 구성한다.

```text
src/
  app/        Next.js App Router 라우팅 (레이아웃/페이지 파일, 얇게 유지)
  views/      라우트별 화면 조합 (FSD의 pages 레이어. Next.js pages 라우터와
              이름이 충돌하지 않도록 views로 명명)
  widgets/    여러 entity/feature를 조합한 화면 단위 블록
  features/   사용자 상호작용 단위 (폼 + 서버 액션): 로그인, 상품 등록,
              매입/판매 등록, 물류 코드 등록 등
  entities/   비즈니스 엔티티별 타입과 서버 조회 함수 (product, purchase,
              sale, logistics-code, stats)
  shared/     공용 UI 컴포넌트, Supabase 클라이언트, 포맷터 등
```

의존 방향은 상위 레이어가 하위 레이어를 참조하는 단방향이다: `app → views → widgets → features → entities → shared`.
